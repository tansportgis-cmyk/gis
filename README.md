# منصة طلبات GIS — دليل التشغيل

تطبيق ويب (HTML + JavaScript) يُرفع على GitHub Pages، وقاعدة بياناته وملفاته على Firebase.

## مسار الطلب

```
الشركة تقدّم الطلب + الملفات  →  GIS يراجع
        ↑                          ├─ ناقص؟  → يرجّعه للشركة مع السبب (مطلوب استكمال) → الشركة تكمّل وتعيد الإرسال
        │                          ├─ مرفوض  → يُبلَّغ الشركة بالسبب
        │                          └─ مقبول  → GIS ينزّل الملفات ويعدّ الخرائط ويرفعها
        │                                       ↓
        │                              يرسلها لقسم الصيانة
        │                                       ↓
        │                     الصيانة تنفّذ وترفع الصور والملاحظات → ترجع لـ GIS
        │                                       ↓
        └──── الشركة تستلم الملفات النهائية ←  GIS: موافقة / رفض / إرجاع للصيانة
```

| الحالة | المعنى |
|---|---|
| جديد | الشركة أرسلت الطلب وينتظر مراجعة GIS |
| مطلوب استكمال | GIS أرجعه للشركة لنقص في البيانات أو الملفات |
| قيد العمل في GIS | GIS يعدّ الخرائط |
| عند الصيانة | الصيانة تنفّذ العمل |
| مراجعة GIS | الصيانة أنهت وتنتظر مراجعة GIS |
| مكتمل | GIS اعتمد الطلب وأرسل الملفات النهائية للشركة |
| مرفوض | GIS رفض الطلب مع ذكر السبب |

> الشركة ترى المراحل الداخلية (GIS والصيانة) باسم واحد: «قيد المعالجة».

## خطوات الإعداد

### 1) إنشاء مشروع Firebase
1. ادخل [console.firebase.google.com](https://console.firebase.google.com) بحساب Google **الخاص بقسم GIS**.
2. اضغط **Create a project** واكتب اسم المشروع، وتقدر تلغي Google Analytics.

> **ملكية المشروع:** حساب Google اللي ينشئ المشروع يصير هو المالك (Owner) تلقائياً. لو أنشأته بحسابك الشخصي وتبي تنقل الملكية لقسم GIS:
> ⚙️ **Project settings ← Users and permissions ← Add member** ← اكتب بريد GIS ← الدور **Owner**.

### 2) إضافة تطبيق الويب ونسخ الإعدادات
1. في الصفحة الرئيسية للمشروع اضغط أيقونة الويب `</>`.
2. اكتب أي اسم ← **Register app**.
3. يظهر لك كود فيه `firebaseConfig`. انسخ القيم وضعها في الملف **`js/firebase-config.js`** مكان `PASTE_...`.

### 3) تفعيل تسجيل الدخول
**Build ← Authentication ← Get started ← Sign-in method ← Email/Password ← Enable ← Save**

### 4) قاعدة البيانات Firestore
1. **Build ← Firestore Database ← Create database**.
2. اختر الموقع ← **Start in production mode**.
3. افتح تبويب **Rules**، احذف الموجود، والصق محتوى ملف **`firestore.rules`** ← **Publish**.

### 5) تخزين الملفات Storage
1. **Build ← Storage ← Get started**.
2. سيطلب منك ترقية المشروع لخطة **Blaze** (الدفع حسب الاستخدام) — هذا شرط من Firebase لتفعيل التخزين. فيه حصة مجانية، واختر موقع التخزين في أمريكا (مثل `us-central1`) حتى تستفيد منها.
3. **مهم:** ضع حد ميزانية حتى لا تتفاجأ بأي مبلغ: [console.cloud.google.com/billing](https://console.cloud.google.com/billing) ← **Budgets & alerts** ← مثلاً 5 دولار.
4. افتح تبويب **Rules** في Storage، والصق محتوى ملف **`storage.rules`** ← **Publish**.
   سيظهر طلب يسمح للتخزين بقراءة Firestore ← اضغط **Allow / Grant**.

### 6) رفع التطبيق على GitHub
1. أنشئ مستودع جديد (Repository) نوعه **Public**.
2. **Add file ← Upload files** ← اسحب **محتويات** مجلد التطبيق (لازم يكون `index.html` في الجذر مباشرة، مو داخل مجلد) ← **Commit changes**.
3. **Settings ← Pages ← Source: Deploy from a branch ← Branch: main / (root) ← Save**.
4. بعد دقيقة يصير الرابط: `https://اسم-المستخدم.github.io/اسم-المستودع/`

### 7) السماح لرابط GitHub بتسجيل الدخول
**Authentication ← Settings ← Authorized domains ← Add domain** ← اكتب: `اسم-المستخدم.github.io`

## 8) جعل حساب GIS هو مدير التطبيق ⭐

لأسباب أمنية، **لا يمكن لأي شخص يسجّل من التطبيق أن يصير GIS**. أول مدير يتم تعيينه يدوياً من Firebase مرة واحدة فقط:

1. افتح رابط التطبيق ← **تسجيل حساب جديد**.
   - نوع الحساب: أي واحد (مثلاً قسم الصيانة)
   - الاسم: «قسم GIS»
   - البريد: بريد قسم GIS
   - بتظهر لك رسالة «حسابك قيد المراجعة» — هذا طبيعي.
2. ادخل Firebase Console ← **Firestore Database ← Data ← users**.
3. اضغط على المستند (Document) اللي فيه بريد GIS.
4. عدّل الحقلين بالضغط على القيمة:
   - `role` ← اكتب: **`gis`** (حروف صغيرة)
   - `status` ← اكتب: **`approved`**
5. ارجع للتطبيق وحدّث الصفحة ← بتدخل مباشرة على **لوحة GIS**.

**بعد هذي الخطوة كل شي يصير من داخل التطبيق:**
- تبويب **الحسابات** ← قبول أو رفض الشركات وقسم الصيانة.
- **تغيير الصلاحية** ← تقدر تعطي زميل في القسم صلاحية GIS.
- **إيقاف** ← يمنع أي حساب من الدخول.
- تبويب **الإعدادات** ← أنواع الطلبات اللي تظهر للشركات.

## 9) تجربة المسار كامل
1. سجّل حساب **شركة** تجريبي (بريد ثاني) ← من لوحة GIS اقبله.
2. من حساب الشركة: **طلب جديد** ← أرفق ملف وحدد الموقع ← إرسال.
3. من GIS: افتح الطلب ← **قبول** ← ارفع ملف في «ملفات GIS» ← **إرسال لقسم الصيانة**.
4. سجّل حساب **صيانة** واقبله ← افتح الطلب ← ارفع صورة واكتب ملاحظة ← **إنهاء وإرسال لـ GIS**.
5. من GIS: **موافقة وإرسال للشركة** ← اختر الملفات اللي توصل للشركة.
6. من الشركة: الطلب «مكتمل» والملفات النهائية جاهزة للتنزيل.

## تثبيت التطبيق على الجوال
- **أندرويد (Chrome):** القائمة ⋮ ← **تثبيت التطبيق** أو **إضافة للشاشة الرئيسية**.
- **آيفون (Safari):** زر المشاركة ← **إضافة إلى الشاشة الرئيسية**.

## الإشعارات
- كل تغيير في حالة الطلب يرسل إشعاراً للجهة المعنية (الجرس 🔔 أعلى الصفحة).
- لتنبيهات الجهاز: افتح الجرس ← **تفعيل تنبيهات الجهاز**. تظهر التنبيهات والتطبيق مفتوح.
- إشعارات الجوال والتطبيق مقفل بالكامل تحتاج إضافة Cloud Functions لاحقاً.

## هيكل الملفات
```
index.html          تسجيل الدخول والتسجيل
company.html        واجهة الشركة (طلباتي + طلب جديد)
gis.html            لوحة GIS (الطلبات، الحسابات، الإعدادات)
maintenance.html    واجهة قسم الصيانة
request.html        تفاصيل الطلب والإجراءات (للجميع حسب الصلاحية)
css/style.css       التصميم
js/firebase-config.js  ← ضع إعدادات Firebase هنا
js/core.js          الدوال المشتركة (الدخول، الملفات، الخرائط، الإشعارات)
js/auth.js · company.js · gis.js · maintenance.js · request.js
firestore.rules     قواعد أمان قاعدة البيانات
storage.rules       قواعد أمان الملفات
manifest.json · sw.js · icons/   لتثبيت التطبيق على الجوال
```

## الحماية (من يشوف إيش)
| | ملفات الشركة | ملفات GIS | ملفات الصيانة | الملفات النهائية |
|---|---|---|---|---|
| الشركة | ✅ ملفاتها فقط | ❌ | ❌ | ✅ بعد الاعتماد |
| GIS | ✅ | ✅ | ✅ | ✅ |
| الصيانة | ❌ | ✅ | ✅ | ❌ |

- كل شركة ما تشوف إلا طلباتها.
- الصيانة ما تشوف إلا الطلبات اللي حوّلها لها GIS.
- عند الاعتماد، GIS يختار بالضبط أي ملفات توصل للشركة.

## ملاحظات
- **تعديل مركز الخريطة:** في `js/firebase-config.js` غيّر `mapCenter` لإحداثيات مدينتك.
- **حجم الملف:** الحد 50 ميجابايت؛ لو غيّرته عدّله في `firebase-config.js` و `storage.rules` معاً.
- **بعد أي تعديل على الملفات:** غيّر رقم الإصدار في أول سطر من `sw.js` (مثلاً `gis-app-v2`) حتى يتحدث التطبيق عند المستخدمين.
- قيم `firebaseConfig` ليست سرية ويمكن رفعها على GitHub؛ الحماية الفعلية في ملفات الـ rules.
